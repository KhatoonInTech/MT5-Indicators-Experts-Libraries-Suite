Correction:
The shared entry filter now walks the latest uninterrupted opposing CHoCH/BOS/sweep sequence in structural-time order, using only event versions available at entry. It requires a causal CHoCH link or a source pivot inside an opposing LB. The LB must be available and active at entry. A candidate-direction event breaks the chain; removed/mitigated sources do not continue vetoing entries. Later zone expansion cannot invent an earlier geometric source link.
The existing InpApplyEntryLBPolicyToPreventionExits filtering remains responsible for admitting qualified LBs into prevention history. The new checks consult that history. The direct pivot-leg guard now uses the selected completed pivot's start, excludes projection pivots, and checks both setup-TF and M1 LB histories. It no longer bypasses qualification via the raw cached-LB array.
Setup-TF structural ancestry is checked even when the selected confirmation leg belongs to M1.
No ZigZag algorithm, LB qualification calculation, partial/full exit policy, stop-loss policy or cluster rules were changed.
The historical OpposingChoch API name and rejection enum are retained for compatibility; diagnostic reasons now identify OPPOSING_STRUCTURE_LB, and direct origins log ENTRY LEG BLOCK.
