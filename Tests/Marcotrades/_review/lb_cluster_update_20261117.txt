LB cluster entry policy - 17 November 2026

Behavior implemented
- One executed entry per connected cluster of same-symbol, same-direction, entry-qualified setup LBs. IND/BSL/SSL subtype and setup timeframe do not separate a cluster.
- Inclusive interval overlap includes containment, exact boundary contact and chains. Register all setup TFs before testing entries.
- Closing a position does not release its cluster. The existing overlap switch/50% TP rule does not override the cluster block.
- Release occurs only when ALL recorded members physically mitigate under the existing LB outer-boundary rule, or the broker date changes. A fresh qualifying LB may then create a new cluster. An already mitigated setup itself never becomes eligible again.
- Mitigated connecting members remain part of the cluster until the last member mitigates. Disappearance/reclassification alone does not clear a consumed cluster; recorded premises can still mitigate using closed setup-TF bars.
- Definite rejected orders release reservations. Accepted or uncertain broker responses retain the block to prevent duplicate entries.
- Live persistence: MQL5/Files/marcotrades/LiveEA/LBClusters_<account>_<scope hash>_<broker-day timestamp>.bin. Scoped by broker server/account/symbol/day. Exclusive file locking, atomic replacement, structural validation. A corrupt or unwritable journal prevents new entries.
- [LB CLUSTER BLOCK] logs identify the candidate and previously consumed cluster member.
- New live tracking starts with entries submitted by this build; old-version trades lack saved setup boundaries and cannot be reliably backfilled. Once recorded by this build, the cluster survives EA/terminal restarts even after the position closes.

Simulation coordination
Previously each timeframe completed its whole history before the next timeframe ran. The new shared clock processes all setup TFs chronologically: structures/mitigations/exits first across TFs, then cluster registration and entries. Earlier eligible trades therefore consume their cluster before later overlapping setups on any TF. Same-timestamp ties use configured TF order. Existing OHLC intrabar fill assumptions remain; this is not tick replay.
The simulator indicator preserves the selected end time through chart reloads. Completed results reload from cache. Reloading an unfinished batch restarts that chronological batch because partially saved chart results cannot reconstruct all active engines/cluster history.
