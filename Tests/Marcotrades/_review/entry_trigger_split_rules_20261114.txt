ENTRY-TRIGGER LB POLICY CORRECTION — 2026-11-14

Scope
-----
This correction changes entry setup eligibility only. Raw liquidity blocks remain
available immediately under the previous rules to entry prevention, rejection
context, and intra-position partial/full exit management.

Corrected entry policies
------------------------
1. BL-LB-IND
   - Requires a valid mitigated BL-IND.
   - Requires two consecutive bullish structural events after that mitigation.
   - Bullish events include BL-BOS, BL-CHoCH, and BSL-Swept.
   - A bearish event resets the consecutive count.

2. BR-LB-IND
   - Requires a valid mitigated BR-IND.
   - Requires two consecutive bearish structural events after that mitigation.
   - Bearish events include BR-BOS, BR-CHoCH, and SSL-Swept.
   - A bullish event resets the consecutive count.

3. BL-LB-BSL
   - Does not require a mitigated BL-IND.
   - Requires the registered BSL-Swept event to remain valid.
   - Requires the immediately adjacent structural event after BSL-Swept to be bullish.

4. BR-LB-SSL
   - Does not require a mitigated BR-IND.
   - Requires the registered SSL-Swept event to remain valid.
   - Requires the immediately adjacent structural event after SSL-Swept to be bearish.

5. Combined BL-LB-IND-BSL / BR-LB-IND-SSL labels
   - Follow the sweep-trigger path because the LB has a concrete BSL/SSL trigger.
   - They therefore do not inherit the IND-only mitigated-inducement requirement.

Additional synchronization fix
------------------------------
If an existing cached IND LB is merged with a BSL/SSL trigger during the current
bar, the simulator now refreshes the authoritative trigger type and sweep time
before evaluating entry eligibility. This prevents a same-bar merge from being
armed by the stale IND-only policy.
